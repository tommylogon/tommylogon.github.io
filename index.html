03 / Systems thinking

The interesting part isn't the LLM.

It is everything around it.

In VirtualWorld, an LLM does not get to redefine reality by describing it. The engine owns the state, validates proposed actions and applies the result according to the world's rules.

03ReasoningGoals and memory

04Proposed actionStructured output

05ValidationRules decide reality
Separate cognition from time.

The world can advance without asking an expensive model to reason about every character on every tick.

Keep identity continuous.

A character remains the same entity with persistent state as its level of simulation changes.

Make behaviour inspectable.

Rules, events, tests and documentation make it easier to understand why the system behaved as it did.

04 / Approach
“I don't just want to make it work. I want to understand why it works.”

I am most engaged when a problem is only partially understood. I break it into smaller questions, test assumptions, trace failures and build a solution around a coherent model of the system.

My work moves between different levels of detail: customer needs, product behaviour, API contracts, database state, implementation, test results and operational constraints. I enjoy learning unfamiliar tools by understanding their underlying concepts rather than treating each technology as an isolated set of commands.

I use AI tools throughout development, from investigation and architecture to implementation and debugging. The goal is not to accept generated code on faith; it is to iterate quickly while checking whether the result actually satisfies the requirements.
